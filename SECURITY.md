# Security policy

WinProof is a read-only forensic differ. Its security properties are mostly
negative — things it does not do — and those are the things worth holding it to.

## What this tool promises

- **No writes.** The probes never call `Set-ItemProperty`, `New-Item`, `Stop-Service`
  or anything that mutates state. The only files written are under `out\` and `store\`.
- **No network.** Nothing in `probes/`, `engine.ps1` or `report.ps1` opens a socket.
  The report is one self-contained HTML file; it loads no external asset, so opening a
  report cannot phone home and a report keeps working offline in five years.
- **Rules are data.** `rules/*.json` is interpreted by a bounded predicate evaluator over
  a fixed operator set (`eq / ne / nonEmpty / isEmpty / hasAny / countGte / in / notIn`);
  an unknown operator throws. A rule arriving from a pull request — or generated by a
  language model — cannot become executable input, and adding one requires no engine change.
- **Redaction is a tested contract, not a promise.** `tools/verify.js` reads the generated
  report and asserts that no absolute home path (raw *and* JSON-escaped form) survives, and
  it pulls the plaintext account/password tokens out of the local facts file and asserts none
  of them appear in the HTML. That check exists because a scheduled task on the author's
  machine runs `rasdial <connection> <user> <password>` and the engine walks that command line.

## What is a vulnerability here

Report it, do not open an issue:

- Any code path that writes outside `out\` and `store\`, or that reaches the network.
- A crafted registry value, preference file or scheduled-task definition that makes the
  engine execute anything, break out of the HTML escaping in `render/template.html`, or
  corrupt the baseline store. The engine parses attacker-controlled JSON and attacker-controlled
  strings, so a parser bug is a security bug even though the tool has no server.
- Identity or secret material reaching a report, including via the committed `demo/index.html`,
  which is published as-is.
- A rule whose evidence field can carry a credential into a screenshot-friendly page.

## What is not

- A false positive. Use the issue template; the fix is usually `ack.bat`, not a disclosure.
- The absence of a rule for a malware family. This tool diffs machine state; it is not an
  antivirus and does not claim to be one.
- Behaviour of PowerShell itself, or of Chromium's preference format.

## How to report

Open a private security advisory against this repository on GitHub
(Security → Report a vulnerability). Do not file a public issue.

Expect an acknowledgement within 7 days. If a report is valid, the fix ships in a release and
the advisory text becomes the release note. This project has no CVE program and no paid support;
it is maintained by one person in their spare time, and that is a fact about response time, not
about how seriously a leak would be taken — a leak of someone's home path or dial-up credentials
into a published artefact is the single worst thing this repository could do.
